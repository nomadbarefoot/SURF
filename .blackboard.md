ROOT CAUSE FOUND: SURF advertises itself as headless at the HTTP layer. httpbin.org/headers shows User-Agent 'HeadlessChrome/148.0.7778.96' and Sec-Ch-Ua '"Chromium";v="148", "HeadlessChrome";v="148"' even with stealth=true and stealth_strategy=aggressive. utils/stealth.py:158 setup_stealth_mode only calls page.add_init_script(bundle), so it patches JS-visible navigator properties but never sets the browser context user_agent, which is decided at context creation. Setting config.user_agent explicitly DOES fix the User-Agent header but Sec-Ch-Ua still reports HeadlessChrome, so UA and client hints disagree, which reads as active spoofing and is a worse signal than plain headless. This is why ko-fi.com/artofayan stays HTTP 403 'Just a moment...': the Turnstile pipeline fully executes (challenge-platform/orchestrate, turnstile api.js, /fo/ POST beacons all 200) but no cf_clearance cookie is ever issued. Egress also exits via a datacenter/VPN IP (146.70.142.138), a second CF risk signal. Future scope: (1) align the launch-level UA and Sec-CH-UA client hints when stealth is enabled, ideally via channel='chrome' or a launch --user-agent flag, so headers are internally consistent; (2) add a deterministic post-navigation clearance wait that polls for cf_clearance and a status transition instead of returning the 403 interstitial as a successful page; (3) reuse persisted profile cookies across sessions (persist_profile already defaults true) so one solved challenge clears later runs; (4) surface an explicit challenge_state field in navigate/fetch output so callers branch on a field rather than an LLM reading 'Just a moment...' out of HTML; (5) investigate the one fetch per navigation dropped with reason outbound_policy in services/session_service.py:719 even with block_mode=off, which never appears in captured network events. Note stealth_strategy accepts none|minimal|balanced|aggressive|legacy; 'full' is invalid.
